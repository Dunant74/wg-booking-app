    SELECT users.name, rooms.name
    FROM bookings
    JOIN users ON bookings.user_id = users.id

    -- Version propre avec alias

    SELECT u.name AS user_name, r.name AS room_name

CREATE TABLE wgs (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    code VARCHAR(20) UNIQUE NOT NULL
);

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    wg_id INT REFERENCES wgs(id)
);

CREATE TABLE rooms (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    capacity INT NOT NULL,
    wg_id INT REFERENCES wgs(id)
);

CREATE TABLE bookings (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id),
    room_id INT REFERENCES rooms(id),
    start_time TIMESTAMP NOT NULL,
    end_time TIMESTAMP NOT NULL
);

SELECT
    u.name AS user_name,

14.2 Amélioration de la base de données :

Oui. On va améliorer surtout avec **contraintes**, **relations** et **règles métier**.

## 1. Vérifier tes tables

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public';
```

## 2. Ajouter des contraintes propres

### `capacity` doit être positive

```sql
ALTER TABLE rooms
ADD CONSTRAINT rooms_capacity_positive
CHECK (capacity > 0);
```

### `start_time` doit être avant `end_time`

```sql
ALTER TABLE bookings
ADD CONSTRAINT bookings_time_valid
CHECK (start_time < end_time);
```

## 3. Améliorer les clés étrangères

Si tes foreign keys existent déjà, ne refais pas cette partie. Sinon :

```sql
ALTER TABLE users
ADD CONSTRAINT fk_users_wg
FOREIGN KEY (wg_id) REFERENCES wgs(id);

ALTER TABLE rooms
ADD CONSTRAINT fk_rooms_wg
FOREIGN KEY (wg_id) REFERENCES wgs(id);

ALTER TABLE bookings
ADD CONSTRAINT fk_bookings_user
FOREIGN KEY (user_id) REFERENCES users(id);

ALTER TABLE bookings
ADD CONSTRAINT fk_bookings_room
FOREIGN KEY (room_id) REFERENCES rooms(id);
```

## 4. Ajouter des colonnes utiles

### Pour les ressources

```sql
ALTER TABLE rooms
ADD COLUMN description TEXT;
```

### Pour les réservations

```sql
ALTER TABLE bookings
ADD COLUMN created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP;
```

## 5. Empêcher les emails vides

```sql
ALTER TABLE users
ADD CONSTRAINT users_email_not_empty
CHECK (email <> '');
```

## 6. Requête de contrôle

```sql
SELECT
    b.id,
    u.name AS user_name,
    r.name AS room_name,
    b.start_time,
    b.end_time
FROM bookings b
JOIN users u ON b.user_id = u.id
JOIN rooms r ON b.room_id = r.id
ORDER BY b.start_time;
```

## 7. Le plus important pour ton projet : éviter les réservations invalides

Déjà maintenant, cette règle est essentielle :

```sql
CHECK (start_time < end_time)
```

Plus tard, on ajoutera aussi la règle pour empêcher deux réservations sur la même room au même moment.

Tu peux exécuter ces commandes une par une dans pgAdmin.
